# Cloudflare Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Change 2026-11-11 (owner's choice):** order email moved from Resend to Cloudflare Email Routing (`ORDER_EMAIL` send_email binding, free to verified destination addresses, no API key). Resend notes below are kept as history; Task 9 is updated.

**Goal:** Run cityfashion.shop on a Cloudflare Worker with orders stored in D1, the owner dashboard behind Cloudflare Access, and Playwright tests that prove an order goes from cart to D1 to email to dashboard.

**Architecture:** `@opennextjs/cloudflare` builds the Next.js 16 app into one Worker. Route handlers reach the D1 binding `ORDERS_DB` through `getCloudflareContext()`. Admin pages and admin API routes verify the `Cf-Access-Jwt-Assertion` JWT themselves (jose, remote JWKS). The order email goes to the Resend HTTP API through `fetch`, with a base-URL override so local tests can point it at a mock.

**Tech Stack:** Next.js 16, @opennextjs/cloudflare, Wrangler 4, D1 (SQLite), jose, Vitest + Miniflare, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-10-cloudflare-migration-design.md` (owner approved 2026-11-11)

## Global Constraints

- Worker name `cityfashion-website`; D1 database `cityfashion-orders`, binding `ORDERS_DB`; migrations in `migrations/`.
- Owner allow list: `sharukesh.seker@gmail.com` (`ADMIN_EMAIL`).
- Public order numbers start at 1001; reference format `CF-<number>`.
- Rate limit: at most 5 attempts per identity in 15 minutes; attempts older than 7 days pruned.
- Identity hash = sha256(`ORDER_RATE_LIMIT_SALT|CF-Connecting-IP|normalized phone`).
- Email failure never fails the order.
- No real secrets in the repo. Local test values live in `scripts/e2e/` and are clearly fake.
- Never bypass Access in production. `ADMIN_DEV_BYPASS=1` only works when `NODE_ENV === "development"`.
- UI copy: very simple English. No stock status. Keep Add to order and the cart obvious on mobile.
- Keep `next.config.ts` host redirects, sitemap, robots, OG/Twitter images unchanged.
- E2E selectors use roles and labels only (no CSS classes, no test ids) so the redesign does not break them.
- Push as GitHub user `sharu28` (switch `gh` before pushing; `ceylonmobility` cannot see the repo).

## Review Focus

- A request without `CF-Connecting-IP` (local, tests): identity falls back to `"unknown"`, order still works.
- The same order submitted twice (double tap, retry after network error): one row, second call returns `duplicate: true`, one email.
- Access JWT for a different email or audience, or expired: admin page shows not found, admin API returns 403.
- Resend not configured or returning an error: order is stored, customer sees confirmation, error logged.
- An admin PATCH with an invalid status change: 400, row unchanged.
